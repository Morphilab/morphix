# Receiving Code Review

## Actitud
Rigor técnico, no agreement performativo. "Tienes razón" sin evidencia es
tan malo como rechazar feedback sin evaluarlo.

## Flujo por cada comentario
1. Entiende QUÉ afirma y POR QUÉ (si no está claro, pregunta).
2. Verifica la afirmación contra el código real/tests — no against tu memoria.
3. Si es correcto: impleméntalo con su propia verificación.
4. Si es incorrecto: responde CON EVIDENCIA (línea, test, salida de comando),
   no con opinión.
5. Los cambios de review también pasan la suite completa.
